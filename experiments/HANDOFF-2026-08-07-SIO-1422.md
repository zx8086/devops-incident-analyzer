## TL;DR

Declare `outputSchema` and return `structuredContent` for exactly 4 tools — `kafka_get_consumer_group_lag`, `kafka_list_consumer_groups`, `aws_cloudwatch_describe_alarms`, `findLinkedIncidents` — with the LLM-visible text output staying byte-identical. `structuredContent` is additive: `@langchain/mcp-adapters` routes it to `ToolMessage.artifact`, which the agent never reads. Success = 4 tools serving validated structuredContent, zero text drift, live smoke probes green. The sharp edge: SDK v1 makes `structuredContent` MANDATORY and schema-validated on every successful call once `outputSchema` is declared — schema/payload drift becomes a live `McpError` instead of a tool result.

## Context — how this ticket came to be

Planned as PR E of the SIO-1409 program (plan: `~/.claude/plans/can-we-look-at-structured-crown.md`, companion design doc alongside it). Blocked until the C-series sugar sweep landed because `outputSchema` requires `registerTool` config style — that landed for all 9 servers on 2026-08-07 (kafka #620 was last). The post-C-8 eval spot-check confirmed the conversion surface held, so wave 1 starts from a verified-stable baseline.

## Where the bodies are buried

The 4 registration sites are all `registerTool` config style now — adding `outputSchema` is a config-object addition per site:

- `packages/mcp-server-kafka/src/tools/read/tools-extended.ts:14` — `kafka_get_consumer_group_lag` (handler wraps via `wrapHandler(...)` at line 20; response built by `ResponseBuilder`).
- `packages/mcp-server-kafka/src/tools/read/tools.ts:66` — `kafka_list_consumer_groups`.
- `packages/mcp-server-aws/src/tools/cloudwatch/index.ts:42` — `aws_cloudwatch_describe_alarms` (schema/handler pattern: `withEstate(config, schema.shape)` + `toMcp(...)`).
- `packages/mcp-server-atlassian/src/tools/custom/find-linked-incidents.ts:246` — `findLinkedIncidents` (returns `JSON.stringify(payload, null, 2)` text; the payload IS the natural structuredContent).

Response seam (kafka): `packages/mcp-server-kafka/src/lib/response-builder.ts:24` — `static success(data: unknown): ToolResponse`. The ticket calls for a NEW `successTyped(data)` returning `{ content: [same text], structuredContent: data }`; leave `success` untouched.

Typed finding shapes already exist: `packages/shared/src/agent-state.ts:150` (`KafkaFindingsSchema`, type export at :204). Per the design, wire shapes live in per-server `output-schemas.ts` files; do NOT import agent-state Zod objects into server packages (see also memory `reference_web_client_no_shared_barrel_value_imports` for the class of import-boundary problem).

Snapshot-fixture interaction: the per-server `tools-list-snapshot.test.ts` hashes ONLY `{description, inputSchema}` — declaring `outputSchema` does NOT drift the fixtures. The eval-safety obligation here is **text byte-identity**, provable with the same temporary zz-capture harness pattern used across C-1..C-8 (mirror the package's `factory-replay.test.ts`, capture pre/post, but for these 4 tools capture a `tools/call` RESULT text with stub data, not just tools/list).

## The fix (step-by-step)

1. Branch off `origin/main`. Per-server `src/tools/output-schemas.ts` (kafka, aws, atlassian): Zod schemas for the 4 tools' wire payloads, derived from what each handler ACTUALLY returns today (read the handler, not the docs).
2. `kafka_list_consumer_groups` FIRST: check live evidence for the bare-array vs enveloped shape before canonicalizing — SIO-1400 counters DB (`bun scripts/mcp-tool-metrics-report.ts` from main checkout) and the spot-check trail `packages/agent/src/eval/fixtures/tool-calls-manifest-default.jsonl` (grep the tool name, inspect `result`). If both shapes occur, declare a union `outputSchema`. Memory: `reference_kafka_rule_state_casing_drift` for known shape quirks.
3. Kafka: add `ResponseBuilder.successTyped(data)` in `lib/response-builder.ts`; switch ONLY the 2 wave-1 handlers to it; add `outputSchema` to their `registerTool` configs.
4. AWS: `aws_cloudwatch_describe_alarms` returns via `toMcp(...)` — add a typed variant preserving the exact text serialization; add `outputSchema`. Fixture shape reference: memory `reference_aws_cloudwatch_describe_alarms_shape`.
5. Atlassian: `findLinkedIncidents` — structuredContent = the existing `FindLinkedIncidentsOutput` payload object; text stays `JSON.stringify(payload, null, 2)`.
6. Per-tool round-trip test per server (factory-replay style): `client.callTool` with stubbed service/bucket/proxy → assert `structuredContent` parses against the declared schema AND `content[0].text` unchanged vs a pre-change capture.
7. Live smoke probes before merge (see Verification).
