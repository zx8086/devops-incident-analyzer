## TL;DR

Pilot the MCP 2026-07-28 protocol via TypeScript SDK v2.0.0-beta on couchbase ONLY, side-by-side: port 9082 stays v1 and untouched (agent `COUCHBASE_MCP_URL` unchanged); a new `server-v2.ts` + `createMcpHandler(factory, { legacy: 'stateless' })` serves both eras on `COUCHBASE_MCP_V2_PORT`. Success = three-era curl verification (legacy 2025-11-25 handshake; stateless 2026-07-28 `tools/call` with `Mcp-Method`/`Mcp-Name` headers; `server/discover`) while all existing v1 tests stay green. Pilot choice rationale: standalone container, fullest surface (tools+resources+prompts), live cluster for verification; KG rejected (embedded in web app), konnect rejected (disabled; reserved for the MRTR pilot, SIO-1426).

## Context — how this ticket came to be

The 2026-07-28 protocol exists ONLY in SDK v2.0.0-beta (package split `@modelcontextprotocol/server|client|core|node`; sugar methods removed — which is why the C-series swept them first; codemod `@modelcontextprotocol/codemod v1-to-v2` exists upstream). The agent client cannot speak it until `@langchain/mcp-adapters` ships v2 support (pins SDK `^1.26.0`), so this pilot is server-side and additive. Plan: `~/.claude/plans/can-we-look-at-structured-crown.md` (F2 section) + companion design doc.

## Where the bodies are buried

- **The two v1-private monkey-patches that must be rebuilt** against v2's public seam:
  - `packages/shared/src/read-only-chokepoint.ts:43` (`installReadOnlyChokepoint`) — reaches into `server.server._requestHandlers` (interface at `:37`, access at `:45`).
  - `packages/shared/src/tool-call-logging.ts:115` (`installToolCallLogging`) — same reach-in (`:47`, `:124`).
  - v2 will not have `_requestHandlers` in that shape. FIRST EXECUTABLE STEP of the whole ticket: install the beta in the couchbase package only and inspect the v2 API surface (request-handler seam, `ServerOptions.cacheHints`, `createMcpHandler` types) — the chokepoint/logging design is contingent on what v2 exposes (prefer native middleware/interceptor hooks if present).
- **Dependency isolation**: v2 beta packages go in `packages/mcp-server-couchbase/package.json` ONLY, at exact versions (NOT `catalog:`). The other 8 servers + agent stay on the v1 catalog. After install, inspect `bun.lock` for (a) the known root-catalog rewrite side effect (memory `reference_bun_install_rewrites_root_catalog` — `git checkout package.json bun.lock` + reinstall if the root manifest changed), and (b) a second zod instance in the v2 subtree (root `overrides.zod = "4.3.6"` should satisfy v2's `^4.2.0`; never share Zod schema objects across the v1/v2 boundary regardless).
- **Bootstrap seam**: `packages/shared/src/bootstrap-lifecycle.ts` (created by F1) is what `bootstrap-v2.ts`/`createMcpApplicationV2` reuses. If F1 has not landed, STOP and do F1 first (`experiments/HANDOFF-2026-08-07-SIO-1423.md`).
- **Registration source**: couchbase's registration is all config-style post C-6/B2 (`packages/mcp-server-couchbase/src/server.ts` `createMcpServerFactory`; resources carry their own `ResourceRegistry` from `src/resources/resource-registry.ts`). The v2 `server-v2.ts` builds its own registration against v2 APIs — do not try to share the v1 factory.
- **Wire-level tests only on the v2 side**: v1/v2 `InMemoryTransport`s cannot link, and avoid depending on the beta v2 client initially — test via raw `fetch()` against the v2 HTTP handler.

## The fix (step-by-step)

1. Verify F1 merged. Branch off `origin/main`.
2. Add v2 beta deps (exact versions) to `packages/mcp-server-couchbase/package.json`; `bun install`; run the lockfile checks above. Commit this alone (easy to bisect).
3. **Discovery spike (throwaway notes in the PR description, not code)**: enumerate v2's server API — how request handlers register, middleware/interceptor seams, `ServerOptions.cacheHints`, `createMcpHandler(factory, { legacy: 'stateless' })` signature. Decision point: chokepoint/logging as middleware vs wrapper.
4. `packages/shared/src/bootstrap-v2.ts` — `createMcpApplicationV2` reusing `bootstrap-lifecycle.ts`. Keep it OUT of the shared barrel until stable.
5. Rebuild read-only chokepoint + tool-call logging against the v2 seam (same behavioral contracts: chokepoint blocks writes irrespective of annotations; logging counts terminal outcomes with `result.isError === true` detection — memory `reference_mcp_no_universal_toolcall_log`).
6. `packages/mcp-server-couchbase/src/server-v2.ts` + transport on `COUCHBASE_MCP_V2_PORT`; declare `ttlMs`/`cacheScope` cache hints for tools/resources/prompts lists (static per-process → public + long TTL).
7. Wire-level tests via raw `fetch()`: the three-era matrix below, plus a `tools/call` result-text equivalence check against the v1 server for 2-3 representative tools (same stub bucket → same text).
8. PR; keep v1 suites untouched and green.

Three-era curl matrix against the running v2 port (start the server, kill it after — track the PID):

```bash
# 1. Legacy era: initialize handshake negotiating protocolVersion 2025-11-25
curl -s -X POST http://localhost:$COUCHBASE_MCP_V2_PORT/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"probe","version":"0"}}}'
# 2. Stateless 2026-07-28: tools/call with _meta protocolVersion + Mcp-Method/Mcp-Name headers
curl -s -X POST http://localhost:$COUCHBASE_MCP_V2_PORT/mcp -H 'Content-Type: application/json' \
  -H 'Mcp-Method: tools/call' -H 'Mcp-Name: capella_ping' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"capella_ping","arguments":{},"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28"}}}'
# 3. server/discover
curl -s -X POST http://localhost:$COUCHBASE_MCP_V2_PORT/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":3,"method":"server/discover","params":{}}'
```

(Exact request shapes may need adjusting to what the beta actually implements — that is part of the step-3 discovery; the plan's shapes are from the spec announcement.) Plus: live agent flow against the untouched v1 port 9082 unchanged. A later, separate, deliberate step (NOT this PR): pointing the agent at the v2 port's legacy mode.

## Risks and edge cases

| Risk | Likelihood | Mitigation |
|---|---|---|
| v2 beta churn invalidating the port | Medium | side-by-side design; v1 path untouched; wire tests not beta-client-coupled |
| No public v2 seam for chokepoint/logging | Medium | discovery spike FIRST; worst case wrap handlers at registration (the C-6-proven wrap-at-seam pattern) |
| Dual zod instances across v1/v2 subtrees | Low-Med | lockfile inspection post-install; no schema-object sharing across the boundary |
| Root catalog rewrite on install | Medium | known side effect — check `git diff package.json bun.lock`, revert+reinstall (memory) |
| Orphaned v2 listener during testing | Certain if forgotten | track PID at spawn; `lsof -nP -iTCP:$COUCHBASE_MCP_V2_PORT -sTCP:LISTEN` must be empty before ending any session |
