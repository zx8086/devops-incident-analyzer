## TL;DR

All six probed datasources (elastic, couchbase, kafka, konnect, gitlab, aws) ship declarative
`workflows/resolve-identifiers.yaml` presets executed by the skillflow executor inside the
`resolveIdentifiers` node, parity-proven against their legacy probes on both fragments AND tool
arguments — but behind `RESOLVE_IDENTIFIERS_PRESETS_ENABLED` which **defaults OFF**, so production
behavior is unchanged. This ticket ships the documentation, makes the flag per-datasource, resolves
the one known latency regression (couchbase preset runs its 3 discovery calls sequentially where
legacy ran them parallel), live-verifies parity per datasource via the web-server replay, and flips
datasources ON one at a time.

## The fix (step-by-step)

1. **Per-datasource flag** (`resolve-identifiers-workflow-handlers.ts`): change
   `isResolvePresetsEnabled(env)` to `isResolvePresetsEnabled(dataSourceId, env)` accepting a
   list-valued env — mirror `bindingsReadDatasources` (`resolve-identifiers.ts:107`):
   `RESOLVE_IDENTIFIERS_PRESETS_ENABLED=couchbase,kafka` opts those in; `all`/`true`/`1` = every
   datasource; unset/`false`/`0` = none. Update the six dispatch sites to pass their id. Update
   the flag unit test + parity suites (they set the env to `"true"`, which must keep meaning all).
2. **Couchbase latency decision** (pick ONE, confirm with the user if unsure):
   a. (Recommended) Add independent-step concurrency to `runWorkflow`: execute each Kahn layer's
      steps whose `depends_on` are satisfied with `Promise.all`, preserving per-step error
      semantics. Benefits every workflow; needs skillflow tests (ordering, failure in a parallel
      layer, SIO-1356 placeholder seeding still per-step). File as its own small skillflow change
      inside this ticket's PR.
   b. Accept sequential for couchbase and record the 3x-timeout worst case in the docs + a
      lowered `RESOLVE_IDENTIFIERS_PROBE_TIMEOUT_MS` guidance. (Cheaper, but the 24s worst case
      on the hot path argues against.)
3. **Docs** (`docs/architecture/agent-concepts.md` §4): add a "resolve-identifiers presets"
   subsection covering: the `raw` output convention (tool step = invoke + normalize -> one `raw`
   output; parsing stays code), the `nodes` registry + fragment-vs-outputs node results, the
   `trigger` payload for focus-derived args, `toToolArgs` (JSON coercion, ""-omission = optional
   arg absent, numeric-string caveat), the multiplied-step convention + `MAX_BRANCH_RAW_BYTES`
   oversize->failed-branch, atlassian's deliberate absence (SIO-1096), and the flag.
4. **Live verification per datasource** (recipe: memory `reference_worktree_web_server_replay_env`):
   run the web server from a worktree with `RESOLVE_IDENTIFIERS_PRESETS_ENABLED=<datasource>`, replay
   a real incident query, and diff the rendered focus block against a flag-OFF run (expect identical
   resolved identifiers). Also kill one MCP server mid-run and confirm the turn still completes
   (soft-fail proof). KILL every started service afterwards; prove ports free with
   `lsof -nP -iTCP:<port> -sTCP:LISTEN`.
5. **Staged flips**: flip default per datasource (order: couchbase -> kafka -> konnect -> gitlab ->
   elastic -> aws, mirroring parity confidence) by changing the flag DEFAULT semantics only after
   its live check passes. Separable commits so one regression reverts alone.
